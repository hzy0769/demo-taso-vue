# Taso 全球化 UI/UX 评审与优化建议

评审日期：2026-09-12  
范围：当前 Vue 原型的欢迎／登录、内容探索、社交、会员卡、钱包、充值、提现、推广与股东分红页面；以欧美、东南亚、香港、台湾、日本、韩国的移动端习惯，以及 iOS App Store / Google Play 上架呈现为参照。  
说明：这是产品与体验评审，不构成针对任何地区的法律或牌照意见。当前原型的黑白金视觉、卡片层级、44px 左右的主要点击区、内容原文与译文分层，整体已经具备现代、克制的国际化社交产品气质；以下为首发前应处理的问题。

**原型边界说明**：本评审认可当前“全量展示需求能力”的原型策略。文中的“隐藏／禁用／地区限制”均是进入真实账号、真实支付或应用商店发布阶段的实施要求，不建议为了原型演示删去这些页面。原型阶段应改为使用明确的 `Demo`、`Coming soon`、`Region-dependent` 或“示例数据”标签，避免评审者误把演示态当成已可在全球真实提供的服务。

## 结论与优先级

| 优先级 | 结论 | 建议首发前处理 |
| --- | --- | --- |
| P0 | 金融、加密资产、推广佣金与“股东分红”在所有用户面前同时出现，容易被理解为受监管金融产品或多层级收益计划。 | 以国家／地区、年龄、KYC、实体与牌照为条件进行能力开关；未开放用户不展示入口，只展示合规说明或候补状态。 |
| P0 | 首次启动固定为“繁体中文（香港）+ 香港内容”，不符合面向全球用户的冷启动预期。 | 按设备语言、时区与粗粒度地区做可跳过的建议，不要把香港设为全球默认。 |
| P0 | 页面视觉隐藏的发布、评论、支付等弹层仍出现在辅助功能树中。 | 设计验收要求：关闭态不可被读屏聚焦；打开态焦点进入弹层、关闭后返回触发控件，且背景不可操作。 |
| P1 | “附近”实际依赖内容地区，不是设备位置；多语言、价格和本地支付语境仍不足。 | 重命名或补齐授权位置流程，并建立市场化文案、货币与支付可用性策略。 |
| P1 | 视觉简洁但小字号、金色文字对比度及无暗色模式，会削弱海外可读性与系统融合感。 | 完成可访问性与动态字体／深色模式规范后再扩展视觉细节。 |

## 1. 先把“全球冷启动”改为建议，而不是预设

### 观察

- 首次欢迎页直出香港繁中，且默认内容地区为香港；这是当前原型中的固定产品规则。
- 对纽约、伦敦、曼谷、雅加达或首尔的新用户而言，首屏语言、城市和内容相关性都可能错误，增加跳出与语言切换成本。
- 东南亚不能只按国家或语言归类：例如新加坡常用英语、中文、马来语和泰米尔语；马来西亚、菲律宾、印尼、泰国与越南的优先语言亦不同。

### 调整方案

1. 首启按 `device language → device region/时区 → English` 给出**可见但可跳过**的建议，例如“Language: English”“Explore: Bangkok”。不要使用精确定位作为默认前提。
2. 将首屏改为“Continue in English / Change language”，内容地区放为次级选项，或在进入 Feed 后用轻量提示询问“Explore content around Bangkok?”。
3. 第一批新增 Thai、Bahasa Indonesia、Vietnamese；视市场策略再加入 Malay、Tagalog。每一种语言都要有完整 UI、通知、空状态、错误与法律文本，避免大量英文回退。
4. 内容地区与账户居住地、收货地址、KYC 国家必须明确区分。前者只影响推荐；后者才决定支付、卡、钱包和加密资产能力。

## 2. 位置、地区与内容推荐的语义需要一致

### 观察

- 探索页的第一个筛选项是“附近”，但当前行为是内容地区排序，并没有位置权限、距离或“离你多远”的解释。
- 海外用户通常把 Nearby 理解为设备当前位置；如果实际只是城市内容，会产生“为什么推荐不在我身边”的信任问题。
- 国家／地区列表用国旗辅助可读性没有问题，但香港、台湾、澳门等名称、旗帜与排序应按 App Store / Play 的当地可售区、语言与法务口径统一，不应由单一市场默认决定。

### 调整方案

1. 若不申请位置权限，将“附近”改为“所选地区”“Tokyo picks”或“Explore by city”。
2. 若提供真实附近：先点击筛选，再用系统权限弹窗前的说明页解释用途、精度、可随时关闭；拒绝后仍保留城市选择。不要首启直接弹系统授权。
3. 地点卡显示 `距离 + 营业状态 + 来源／更新时间`；无精确位置时不显示“附近”。
4. 地区命名建立独立配置表：以用户 UI 语言显示当地常用名称，并让法务确认敏感地区的名称、旗帜和市场可见性。

## 3. 金融功能需要“能力分层”，不能只靠一个已通过 KYC 的页面

### 观察

- 会员卡充值、可提现钱包、银行卡、USDT／USDC、三层推广奖励和股东分红都在同一产品内，且原型中几乎可被所有用户进入。
- “Shareholder”“Dividend”“3 级收益”“充值分佣”等表达，对欧美、日韩与部分东南亚用户可能被理解为证券、投资回报或多层级营销，而非普通会员权益。
- 原型使用同一个 USD 账本，同时出现港币办卡费、美元运费、稳定币估算和 16% 充值费；用户很难快速判断实际扣款货币、费用、税费与退款规则。

### 调整方案

1. 建立服务能力矩阵：`用户居住地 / KYC 级别 / 年龄 / 产品实体 / 支付方式 / 币种 / 风险等级 → 可见、可申请、可交易、只读`。入口、深链、通知和客服话术都使用同一矩阵。
2. 未开放市场不显示可点击的 USDT／USDC、提现、分红与推广收益入口；以“此功能暂未在你所在地区提供”替代事后阻断。不要仅靠 UI 语言判断。
3. 将“会员消费余额”“可提现收入”“加密资产支付”“股东权益”分成可清楚解释的独立账户／产品，不要归在一个 `Benefits` tab。建议底栏保留“会员”或“钱包”其中一个，另一个由二级入口承载。
4. 每次付款前固定展示：计价币种、扣款币种、汇率来源与有效时间、平台费／网络费／税费、到账金额、退款规则、商户／收款主体和客服入口。使用 `JP¥3,800`、`HK$…`、`US$…`，而不是只用易歧义的 `¥`。
5. “股东”身份不可由个人资料页的交互切换；产品体验上应仅在后台审核和合法披露完成后显示。收益页必须有风险提示、资格状态、披露文件、历史与预计值的明显区分，且不以“获利”作为泛化营销。
6. 推广计划先改为单层、非现金或经合规确认的奖励模型；若保留现金和多级结构，应在进入前展示市场资格、完整条款、反欺诈／反刷单规则和税务提示。

### 平台审核依据（需在上线时再次核验）

- Apple 要求使用第三方社交登录作为主账户登录的 App 同时提供符合条件的等效登录方式；当前已提供 Apple 登录，方向正确，但应使用官方组件和完整原生授权流。[Apple App Review Guidelines 4.8](https://developer.apple.com/app-store/review/guidelines/)
- Apple 要求 Apple Pay 在支付前展示完整购买信息并遵守品牌与界面规范；因此 Apple Pay / Google Pay 只应在设备、浏览器、地区、商户和支付方式均可用时出现。[Apple App Review Guidelines 4.9](https://developer.apple.com/app-store/review/guidelines/)
- Apple 对加密钱包、交易和加密证券类服务有组织主体、许可和地区限制；Google Play 也要求加密交易／钱包在受监管辖区通过合规服务提供，并可能要求资料证明。[Apple Guidelines 3.1.5](https://developer.apple.com/app-store/review/guidelines/)、[Google Play 加密政策说明](https://support.google.com/googleplay/android-developer/answer/16329703?hl=en)
- Google Play 对数字内容／功能通常要求使用 Google Play Billing；实体商品和实体服务属于不同情形。会员权益、数字内容、会员卡、充值余额和打赏必须逐 SKU 判断，不可用“实体生活服务 App”一概处理。[Google Play Payments policy](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en)

## 4. 登录与权限体验：保留已有优点，补齐生态细节

### 已有优点

- Apple、Google、X、邮箱／手机号并列，且提供条款和隐私入口；OTP 有倒计时、错误与锁定状态。
- 登录页明确说明不在登录时索取通讯录、相片和精确定位，这是很好的隐私预期管理。

### 调整方案

1. iOS 使用 Apple 官方 “Sign in with Apple” 按钮的字形、留白、最小尺寸与原生授权 sheet；Android／Web 上让 Google 登录遵守官方品牌组件。不要用自绘近似品牌按钮替代 SDK 输出。
2. 根据平台排序：iOS 上 Apple 第一，Android 上 Google 第一；X 放到“更多方式”中，避免与两种系统身份服务争夺首要层级。
3. 将“继续即同意”改为链接到可按语言／地区打开的版本化条款、隐私、社区规则；涉及内容推荐、翻译、广告、位置和金融信息时，用单独的说明和同意管理，而不是将所有授权塞入注册语句。
4. 手机号使用国家区号选择、E.164 校验、短信资费／运营商提示和改号恢复路径；邮箱注册增加反枚举提示与账户恢复支持。

## 5. 社交内容的跨文化可理解性

### 观察

- 原文、翻译标记和“显示原文”方向正确；但繁中首页仍会首先遇到没有可用中文译文的整段英文内容。
- 页面用“已核销消费／Verified Purchase”建立信任，但没有告诉用户验证的含义、商户是否参与、评论规则，或赞助内容如何标识。
- 发布、评论、好友与聊天可用，但首发全球 UGC 需要对举报、屏蔽、未成年人、商家利益关联与翻译错误提供清晰的用户路径。

### 调整方案

1. 以“有当前 UI 语言高质量译文”的内容优先填充首屏；无译文内容显示原文语言与“翻译不可用”，不要只放一个可能失败的“翻译”动作。
2. 将机翻标记改为明确、可点开的“Translated automatically”；提供“原文／译文”“报告译文问题”。餐饮、价格、过敏原与安全建议不应因机器翻译而被过度保证。
3. 给“Verified Purchase”增加说明页：验证的是何种交易、是否影响排序、可否撤销；广告／合作商家须用醒目的 “Ad / Sponsored / Partner” 标识，不能仅靠灰色小字。
4. 在帖子更多菜单、聊天和个人资料提供真实可达的举报、拉黑、静音和安全中心；发布入口加入可见范围、素材版权、地点精度和评论控制。

## 6. 视觉与无障碍：保留克制风格，提升可读性与系统感

### 观察

- 白底、黑色主操作和少量金色强调的高级感适合旅行／生活方式定位，信息卡和图片比例也干净。
- 底部 tab 文案约 10px、辅助文字约 11px，金色文字在白底上对比不足；对于老年用户、强光环境和系统放大字体并不稳健。
- 当前只有浅色主题。欧美和日韩主流用户对系统深色模式、动态字体、屏幕阅读器与键盘焦点的预期较高。
- 视觉上关闭的弹层仍被读屏识别，属于可访问性阻断，不是细节问题。

### 调整方案

1. 普通正文使用至少 14–16px；tab 文案至少 11–12px，且接受系统字体缩放后仍不截断。辅助文字不要承担关键金额、状态或限制信息。
2. 金色仅作装饰或搭配深色底；所有可交互金色文字、成功／警告状态采用通过 WCAG AA 的前景／背景组合，并另加图标和文字，不只靠颜色。
3. 设计浅色／深色 token 对，并优先跟随系统；图片、半透明顶部栏、支付卡和底部 tab 在两种模式都要验收。
4. 明确无障碍验收项：关闭态 sheet／dialog `不可聚焦且不可读`；打开时焦点陷阱、Esc／返回关闭、焦点复位；每个图标按钮有本地化可读标签；验证错误用文本即时宣告；图片有有意义的 alt 文案。
5. 为横向 chip、长语言、日文／韩文、动态字体 200% 和 RTL 做截图验收。即使第一阶段不支持阿拉伯语，也应避免在布局上写死左右方向。

## 建议的落地顺序

1. **P0 上架闸门**：金融能力矩阵、地区禁用态、股东／多级推广下线或合规隔离、支付披露、登录品牌组件、读屏弹层修复。
2. **P1 首发体验**：设备语言／地区建议、泰语／印尼语／越南语、附近语义与位置授权、货币／税费／价格格式、内容翻译优先级与广告标识。
3. **P2 品质完善**：深色模式、动态字体、完整安全工具、地区名称治理和更精细的支付方式排序。

### 建议的实施组织方式

1. **原型修订卡**：只增加 demo／地区相关标签、解释文案、异常／空态和交互注释，不删任何功能入口；优先处理默认香港、Nearby、资金产品与股东身份的语义。
2. **平台化基础卡**：建立 `MarketCapability`（国家／地区、实体、KYC、年龄、支付与金融能力）和 `Quote`（费用与币种）两个领域模型，再让页面读取它们的展示状态。
3. **上架集成卡**：替换为实际 Apple Sign in、Google Sign-In、Apple Pay、Google Pay、支付／KYC／加密服务商 SDK，并按真实商户与市场配置做端到端验收。
4. **质量验收卡**：覆盖 VoiceOver、TalkBack、动态字体、深色模式和首发语种；将页面截图按设备与市场条件保留为回归基线。

## 验收清单

- 在 iOS、Android、Web 各以香港、台湾、日本、韩国、泰国、印尼、新加坡、美国、英国账号／设备条件验证：首屏语言、内容地区、可用支付方式和金融入口是否正确。
- 无位置权限时不出现暗示真实距离的“附近”；拒绝权限后可完整使用城市探索。
- 使用 VoiceOver / TalkBack 顺序浏览：隐藏发布、评论、支付弹层不会被读到；弹层打开后只有其中内容可被聚焦。
- 大字体、深色模式与英语／泰语／日语／韩语的长文案没有截断、重叠或仅以颜色传递状态。
- 每一个付款、充值、提现、加密资产和奖励流程都能在确认前看到币种、费用、到账、资格限制、收款主体与支持入口。
